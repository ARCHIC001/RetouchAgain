# 协议、请求与资源原则

> 发布派生版/非历史原稿。本文说明算法协议与 policy defaults，不含真实费用、请求标识、实验成功率或摄影成绩。

## 1. 四层合同各有职责

运行协议描述一个独立任务的范围、资源、输入资格和冻结依据。
阶段提交合同约束 `photo_stage_turn` 的公开字段、当前合法动作及 revision。
资源配置定义模型、生成分配、附件和监测策略；它不是实际已消费用量。
执行记录保存实际派发、回执、工具动作、版本和图像；模型不能自报这些事实。
当前源码使用 `dsh-stage-runtime/v2` 与 `stage-contract/v3`，修订需在完整边界一致。

本发布快照不带原运行配置、冻结协议和授权文件。
协议字段或版本名称的存在，不表示克隆后自动获得运行资格。
独立环境的重新接入见[范围与环境](scope-and-environment.md)。

## 2. 一个模型回合、一个复合提交

DSH 每轮提交一个 `photo_stage_turn`，包含公开复核、bank 差异、明确选择和一个行动。
`contract_revision` 与该次实际提供的工具 schema 相同。
adapter 校验 provider 返回结构；工具执行 guard 与 worker 使用同一合同。
公开完整 JSON 文本可经定义的解析路径进入同一个提交，不增加另一种摄影协议。
raw、canonical、warnings 分别留存；结构规范化不生成/裁剪 Native 参数。
需要更正的 schema 问题可反馈 DSH，不由宿主替模型选择摄影数值。

## 3. 图像与上下文的实际投递

每次视觉决策使用两个登记附件，角色是 target/current 或 actual-parent/current。
总览最长边 512，局部最长边 384；派生为 upright RGB8 sRGB PNG。
body、工具 schema、角色、观察和实际附件登记相互对应，不拿本地引用冒充已送达。
prepared 是准备，sent 是实际派发，receipt 是实际收到的供应商回执。
缓存命中减少某些成本，但缓存图像不自动成为新的视觉证据。

工作包优先保留当前组、实际上一操作的完整预期、待复核和下一候选。
长原文与历史分页检索，不每轮重发全后端目录和全部 bank。
完整记录继续本地保存，未投全文不等于删掉知识。
不截断显式参数、当前保护前提或尚待复核的完整预期来凑长度。

## 4. 模型和 64K 生成分配

源码资源默认模型为 `deepseek-official` / `deepseek-flash`，effort 为 `high`。
这是本算法快照的模型选择，不保证供应商名称、价格或可用能力永久不变。
默认 `requested_output_tokens = 65,536`，即约 64K 的请求生成分配。
它是传给运行时的输出预算，不是实际输出量，也不是强制模型必须生成这么多。
静态资源记录的 provider context 为 1,000,000，最大 output 为 393,216。
这些容量声明应在实际接入时向供应商重核，不作为本发布仓库的服务承诺。

日常工作上下文 guidance 为 32–64K，较宽 guidance 为 128K。
它们不是本地字节准入门，不把字符数简单当精确 tokenizer 结果。
不因公开解释略长或超出旧短字段长度就拒绝一个合法动作。
模型和传输仍有真实容量上界；超出时应修订投影和检索方式，不篡改行动。

## 5. 50 是编排参考

规划模板为四个检查点、Tone 18、Color 16、Joint 8 和机动 4，共 50 次。
它是资源分配起点，不是硬请求上限、最低用量、原生编辑次数或摄影质量指标。
分支份额可调剂，提前完成就结束，不为用满槽位制造编辑。
同一问题/组可以多轮；默认顺序可跳过和回访。
需要额外全图、ROI 或 JPEG 重检时，按实际请求计账而非维护“四次”的表面数字。
不自动把独立单图安排扩大为批量样本、多个条件或多次重复。

## 6. 至少分开四种计数

| 计数 | 记录对象 | 避免的误解 |
|---|---|---|
| model_requests_sent | 实际模型派发 | 两张附件不是两次请求 |
| distinct_visual_evidence | 新的真实图像依据 | 重发同图不算新后果 |
| native actions/renders | 实际后端写入和渲染 | 一次模型回合可能包含多步原生事务 |
| tokens/cost/time | 回执用量与运行消耗 | 请求数不能推导总费用或计算量 |

未派发的准备包不算模型已经观察。
派发可能发生但回执未知时保留 pending 与预留，不把未知自动退回成“免费未执行”。
确定性本地检索不额外调用模型；若检索结果引发下一次模型派发，那次仍是实际请求。
thinking token 若为输出总量的子项，不能重复加计为第二份输出。

## 7. 费用采用宽松监测而非形式卡线

原则是使用实际 receipt 估价，区分输入、cache write/read、输出及供应商服务层。
预算提示、参考水平与异常暂停是不同层次，不按每个分支精确切金额。
不使用极端最大输出预留反复拦住下一合法动作，也不因“50 只是指导”无限收费。
显著异常单次消耗、持续无进展或实际费用/计量身份不明时暂停核对。
定价表和阈值由独立环境在明确授权下配置；本文不发布项目真实账目或历史估价。
费用估计不是账单，过期定价不冒充当前服务报价。

## 8. 保留的真实边界

- 当前任务范围、源图职责、阶段家族、真实 ID、单位和数值范围仍严格校验。
- 两图及可辨显示限制保留，图像/几何/ICC 身份不因上下文较宽而放松。
- 传输保险默认 body/response 各 16 MiB、text 4 MiB、timeout 600 秒。
- 原生状态、回执、持久记录不一致或 pending/unknown 时停止核对。
- 单一 scope 的独占 lease 和未知结果不重放原则保持。
- 最终确认依赖实际 JPEG，返修后旧确认失效。

这些是可靠性约束，不是把每次摄影不确定变成额外模型审批。
已证明未执行的结构/选组问题可反馈更正；未知执行不能伪装成这种拒绝。

## 9. prepare、freeze 与显式授权

metadata-only prepare 建立新的任务协议和索引，不转换 RAW 或渲染照片。
真实基线制备是单独明确许可的 Native 操作，不属于普通离线预检。
实际检查目标和基线角色后，freeze 固定当前输入、源设置和合同依据。
付费运行仍需新的显式授权，停止标记、policy 禁用和 circuit 不因文档/代码更新而解除。
若从闭合检查点继续，先检查实际设置、源图与产物身份，再进入新 scope。
不把续接当成盲重放，也不自动复用旧授权。

## 10. 源码与原职责相对来源

`src/photo_stage_resources.json` 是资源配置的单一来源；本页不复制环境配置。
`src/dsh_stage_adapter.mjs` 管理请求/回执/诊断，`src/photo_request_primitives.mjs` 提供共享请求基础。
`src/dsh_stage_validation.py` 管理 prepare/freeze，`src/photo_stage_continuation.py` 管理闭合检查点资格。
`src/photo_authorization_window.py` / `src/dsh_stage_authorize.py` 管理显式授权边界。
