# 架构：单一 DSH 主体与分级摄影循环

> 发布派生版/非历史原稿。本文按设计职责与当前源码重新编排，不是原稿复制、历史恢复稿或实验报告。

## 1. 系统分工

VISHARNESS 把视觉比较、摄影建议和小步编辑组织成可追溯的串行循环。
摄影判断发生在 DSH 内部的同一个 agent 中，不由外层发布工具或操作人员逐轮选参数。
DSH 决定问题、优先级、数值、取证、选版及结束；worker 记录事实并验证当前动作。
Python 会话是阶段、版本、建议 bank、实际操作和公开复核的唯一权威状态。
JavaScript 层负责接入 DSH、投影工作包、登记图像、替换动态工具 schema 和核对请求回执。
观察派生、范围校验与执行器不自行生成摄影目标，也不从散文中猜参数。

完整链条为：

```text
实际两图 + 当前工作包
  → DSH 公开复核 / 建议更新 / 明确行动
  → 当前合同校验
  → 实际操作 / 设置读回 / 全尺寸渲染
  → 真实子版本 / 下一次观察
```

## 2. G1—G4 与三个分支

| 环节 | 实际图像与任务 | 状态产出 |
|---|---|---|
| G1 | 彩色作者目标与真实后端基线 | 明暗、颜色、耦合问题及保护对象；建立 bank |
| Tone | 一致灰度目标/当前，或实际父/子 | 少量影调假设、小步编辑、后果复核与影调选版 |
| G2 | 彩色目标与影调选中版 | 增量重评颜色问题，更新优先级和复核债务 |
| Color | 彩色目标/当前，或实际父/子 | 逐组调整颜色，并检查已接受影调是否退化 |
| G3 | 彩色目标与颜色选中版 | 整体协调、影调回退、区域边界与少量综合残差 |
| Joint | 实际彩色全图及必要局部 | 围绕明确残差联合微调、选版、实际导出 |
| G4 | 彩色目标与实际 JPEG 的观察派生图 | 确认交付、partial 或未确认，并保留未解决项 |

四个 G 是职责检查点，不是“必须刚好四次模型请求”。
必要的局部补证、分支回访和 JPEG 再检查仍是实际观察，需要如实计入资源。
G2 可回 Tone，G3 可回 Tone/Color，G4 可回 Joint；后续检查点随返修重新成立。
G4 返修使旧 JPEG 确认失效；即使未再改参数，也须新导出并实际再看。

## 3. 分支、有序模块与细组

任务层次是“问题 → 分支 → 有序模块/步骤 → 细组 → 多轮观察和动作”。
一个问题可以跨分支保存多个建议，但执行时只选择当前明确细组。
细组不是固定的参数个数，而是有共同摄影假设、可解释后果的一组控制。
点曲线、WB 单位和共享蒙版几何保留整体语义，不按单个数字机械拆散。

默认路线如下。

- Tone：曝光 → 对比 → 高光/阴影 → 白场/黑场 → Master 点曲线 → 参数曲线 → 必要局部影调 → 收束。
- Color：G2 重评 → 全局 WB → 必要 Calibration → 全局彩度/HSL 主色关系 → 必要分级 → 局部 WB → 收束。
- Joint：按 G3 的残差选择相关影调、颜色、曲线、质感或局部小组，而非重走全部菜单。

该顺序用于组织和推荐，不是渲染器计算顺序，也不是操作权限的替代品。
DSH 可以跳过不需要的步骤、提前处理局部瓶颈、回访已做模块；选择理由与重排来源留存。
同一细组可多轮小步调整，没有“动一次就完成”或“每组必须用满轮数”的规则。
同阶段跨步骤联合组须明确命名、共同假设和理由；宿主不静默切掉部分 action。
HSL 的 Luminance 仍属颜色任务；Texture/Clarity/Dehaze 属综合任务。

## 4. 一次复合提交

公开入口是 `photo_stage_turn`，不是彼此脱节的“提议—再次确认—执行”仪式。
提交携带当前 `contract_revision`，其 schema 与实际请求、adapter、worker 使用同一修订。
主要内容包括：

- `review`：当前实收图比较、上一真实后果及公开判断；
- `bank_delta`：建议的新增、保持、修订、延期或撤销；
- `selected_issue_id` / `selected_group_id`：将动作明确关联问题与细组；
- `selection_reason` / `override_reason`：采用、越过默认顺序或返回前组的理由；
- `review_debt_updates`：跨阶段副作用复核或明确取舍；
- `action`：当前完整操作，或观察、检索、转阶段、选版、导出、结束。

同一返回可复核旧后果、修订 bank 并执行下一合法组，不普遍增加收费确认轮。
实际编辑绑定五字段预期：目标、预期变化、保护对象、风险和反证条件。
非法结构可反馈更正；未知执行状态不靠重新询问模型来推断或重放。

## 5. 当前计划与真实发生分开

`current plans` 指当前相关提议、排序、依赖和预期；它们随新观察改变。
`actual` 指后端操作、实际设置读回、父子版本、实际渲染及实际送达图像。
prepared/projected 不是 delivered；delivered 也不是模型已经公开复核。
新建蒙版的别名不是原生 ID；建议中的数值不是已应用参数。
执行成功不证明图像改善，支持一次预期也不证明作者目标已经达到。
模型判断、技术检查与作者认可分别保存，不相互升级身份。

选早期最佳版不删除后代；离开所选祖先链的判断与复核债务保留其原分支身份。
工作包只投递当前有关任务；未投全文继续可检索，不能把“不在上下文”写成“已不存在”。
细节见[记忆与任务路由](memory-and-task-routing.md)及[观察与色彩](observation-and-color.md)。

## 6. 源码职责定位

- `src/dsh_stage_run.mjs`：运行组合与 DSH agent 循环；当前仍有特定单任务资格假设。
- `src/dsh_photo_runtime.mjs`：接入外部 DSH、工具快照和会话投影。
- `src/dsh_stage_adapter.mjs`：实际请求、结构反馈、回执和资源诊断。
- `src/dsh_stage_worker.py`：权威会话、复合提交与执行编排。
- `src/photo_phase_scheduler.py`：阶段、检查点、返修和复核债务。
- `src/photo_stage_tasks.py` / `src/photo_proposal_bank.py`：任务注册、细组、提案历史与工作包。
- `src/photo_stage_schema.py` / `src/photo_stage_operations.py`：动态合同与受限操作。

这些是发布源码的职责地图，不表示外部依赖齐全或已具备新的运行资格。
源码快照与恢复要求见[范围与环境](scope-and-environment.md)。
