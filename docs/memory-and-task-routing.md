# 工作记忆、建议库（Bank）与任务路由

多轮调色中，模型既要记住“画面最初有哪些问题、计划怎么改”，又要清楚“刚才到底执行了哪一步、效果怎么样”。VisHarness 通过工作记忆与建议库（Proposal Bank）将规划、执行和复核串联起来。

## 1. 三类信息分层

在同一个 worker 会话中，系统将信息划分为三个正交层次：
1. **工具知识**：控件名称、单位、取值范围及原生算法边界。
2. **建议库（Proposal Bank）**：当前画面的诊断问题（Issue）、拆解细组（Group）及动态调整计划。
3. **执行账本（Execution Ledger）**：实际发送到后端的操作、父子版本链、参数读回与每轮视觉复核结论。

## 2. 幂等提交规范化

模型提交的 JSON 经 `photo_stage_submission.normalize_submission` 进行幂等规范化，运行日志同时留存原始提交 `raw`、规范化结果 `canonical` 以及结构提示 `warnings`：
- 自动将嵌套在动作参数中的 `selection_reason` 提取到顶层、将带有实际参数改动的 `keep` 归类为 `revise`，并对 `effect` 同区 ROI 表达做确定性归一。
- 仅整理结构而不替模型猜参数或裁剪动作；若存在字段缺失或类型错误，直接返回清晰的结构反馈供下一轮修正。

## 3. Issue 与细组（Group）的数据结构

- **Issue**：保存初始诊断、分类、优先级与完整的修订历史。
- **细组（Group）**：归属于特定 Issue，记录所属分支与模块、当前绝对参数、依赖关系、目标变化、保护区域、风险点及关联的复核记录。

细组拥有跨轮次的稳定 ID。当上游的曝光、全局白平衡或共享蒙版几何发生大幅改动时，下游关联的 HSL、色彩分级或局部细组会被标记为 `needs_reassessment`，提示模型基于新渲染重新评估，而不是盲目沿用旧参数。

## 4. 独立的状态维度

系统用一组清晰的正交状态描述任务进度，避免将“命令调用成功”误判为“调色目标已达成”：

| 维度 | 典型值 | 作用 |
|---|---|---|
| **Issue 生命周期** | `active` / `deferred` / `retired` | 跟踪该问题是否仍在当前关注范围内 |
| **细组调度** | `ready` / `current` / `later_phase` / `waiting_dependency` | 指示当前焦点任务与阻塞原因 |
| **证据有效性** | `needs_reassessment` / `off_selected_branch` / `unresolved` | 标记上游变动后是否需要重评，或是否已脱离主分支 |
| **操作后状态** | `awaiting_effect` | 已写入后端，等待下一轮 `effect` 视觉复核 |
| **任务处置** | `resolved` / `retired` | 模型对该任务项的显式结案 |
| **实际操作** | `operation / base / child / actual_params` | 真实发生的后端读写与版本事实 |
| **后果判断** | `supported` / `contradicted` / `mixed` / `uncertain` | 模型对上一轮操作实际效果的判断 |
| **目标结论** | `matched` / `partial` / `unresolved` | 最终画面与作者目标的接近程度 |

## 5. 软依赖、Override 与回访机制

默认模块顺序和同 Issue 内的依赖关系由 `photo_stage_tasks` 解析。依赖在 VisHarness 中属于**软性顺序提示**：如果模型基于当前画面认为需要先解决某个下游瓶颈，只要完成重评并给出明确的 `override_reason`，即可跳过等待直接推进。

对于已显式标记为 `resolved` 的细组，后续编辑不会自动将其重新打开；若后期观察发现需要返修，模型可基于新图像显式修订并说明重开依据。

## 6. 单轮闭环与拒收隔离

标准单轮推进在同一个 `photo_stage_turn` 内完成：**收图 → 复核上一步效果 → 更新建议库 → 选定下一细组 → 校验并执行动作**。

如果本轮动作在写入原生后端前因校验失败被拒绝，系统会保留本轮合法的建议库更新，并仅针对动作错误返回提示，不产生新版本也不结清复核债务；如果操作已穿过持久写入边界且回执不明，则立即停机核对现场。

## 7. G2 增量重评与跨阶段复核债务（Review Debt）

进入 G2 后，模型基于影调定稿版逐项评估色彩建议（`keep / revise / retire / new / uncertain`）。

针对跨阶段的联动效应（如 Tone 阶段调整带来的色彩偏移、Color 阶段对亮度的影响、或共享蒙版几何变动），系统通过**复核债务**追踪，确保在下一检查点或关联阶段得到公开复核。若中途选择回退到早期版本，离开主线分支的债务会自动标记为 `not_applicable_selected_branch`。

## 8. 工作包（Working Package）投递

为在有限上下文窗口内保持高信噪比，每轮工作包优先投递：当前焦点细组、上一真实操作的完整五字段预期、待复核项、少量后续候选组，以及延期/等待任务的摘要。完整历史与长文本保存在本地账本中，模型可通过游标按需分页检索。

## 9. 对应源码模块

- `src/photo_stage_submission.py`：提交规范化与结构警告。
- `src/photo_proposal_bank.py`：建议库存储、操作账本与工作包生成。
- `src/photo_stage_tasks.py`：任务注册、默认路线与软依赖解析。
- `src/photo_phase_scheduler.py`：阶段调度与复核债务管理。
- `src/dsh_stage_worker.py`：复合提交统一入口。
